# 反应训练页面浅色化与紧凑布局修复设计

## 背景与目标

当前 `reaction-training` 已将共享页面框架改为浅色，但三个游戏页仍保留深色游戏区域和控件；同时，游戏页在常见笔记本视口中需要滚动才能看完整个主要操作区，打地鼠漏掉目标时的提示也不够醒目。

本设计覆盖并替代原始设计中关于游戏页深蓝训练面板的视觉要求。修复后的三个游戏页需要满足以下目标：

- 页面、游戏区域、选择框和数字按钮均使用统一浅色界面。
- 在 1366×768 的桌面视口中，无需滚动即可看到完整的主要游戏区和操作控件。
- 手机端保持自然滚动，并保留足够大的触控目标。
- 打地鼠漏掉目标时提供醒目但不中断训练节奏的反馈。

## 方案选择

采用“统一浅色令牌 + 紧凑游戏页布局”的方案。该方案保留现有 HTML 页面、游戏控制器和核心逻辑，只调整共享样式、游戏专用样式及打地鼠反馈状态，避免为视觉问题重写游戏结构。

不采用单纯覆盖深色颜色的最小补丁，因为它不能可靠解决 1366×768 下的页面溢出；也不重做三个页面结构，以免扩大回归范围。

## 视觉系统

共享浅色体系继续以现有变量为基础：浅蓝灰作为页面底色，白色作为主要游戏表面，深蓝作为正文文字，青色作为导航和聚焦辅助色，橙色作为主要动作与目标色。

三个游戏区的具体调整如下：

- 见缝插针：画布背景、圆盘和针改为能在白色面板上清晰区分的浅色组合，碰撞和发射仍使用高对比橙色提示。
- 打地鼠：游戏场地改为白色或极浅蓝灰，未激活地洞使用中性浅灰，激活地鼠继续使用橙色，保证目标识别速度。
- 数字消除：数字按钮改为浅色卡片和深色数字；悬停、键盘焦点和错误反馈分别使用青色与橙红色边框。
- 下拉框：使用白色背景和深色文字，不再使用页面底色作为深色填充。

## 紧凑桌面布局

游戏页增加专用的紧凑布局语义，不影响主页。桌面端以 1366×768 为最低一屏验收基准：

- 缩小游戏页顶栏、面板上下内边距、标题区间距和控件间距。
- 游戏面板使用可用视口高度计算主要区域尺寸，避免固定大尺寸叠加造成纵向溢出。
- 见缝插针画布使用受视口高度与容器宽度共同约束的正方形尺寸。
- 打地鼠场地在桌面端使用受视口高度约束的高度，并维持全部地洞的安全分布范围。
- 数字棋盘根据阶数和可用高度控制单元尺寸与间距，6×6 仍保持可点击性。
- 结果面板仅在一局结束后显示；显示结果时允许页面自然滚动，不要求游戏区和结果区同时塞入 768px 高度。

在窄屏和触控设备上取消强制一屏高度，页面恢复自然文档流；按钮和地洞尺寸不得因压缩而低于现有移动端可用水平。

## 打地鼠漏掉反馈

漏掉目标时同时触发三个信号：

1. 游戏区上方显示红色提示条，文本为“漏掉了！还可漏掉 N 次”。
2. 顶部“漏掉 X/3”计数短暂切换为红色强调状态。
3. 游戏场地边框和浅红内阴影执行一次短促闪烁。

反馈不添加暂停，不改变下一只地鼠的调度逻辑。命中目标或新一局开始时清除残留的漏掉反馈状态，避免提示永久停留。屏幕阅读器继续通过现有 assertive live region 收到漏掉消息；在 `prefers-reduced-motion: reduce` 下取消闪烁动画，但保留颜色和文本提示。

## 代码边界与数据流

- `assets/styles.css` 负责共享浅色令牌、游戏页紧凑布局和通用控件样式。
- 三个游戏 HTML 中的专用样式只保留各自游戏区域的几何和状态表现。
- `needle.js` 仅调整画布绘制色值，不改变旋转、发射或碰撞逻辑。
- `whack-a-mole.js` 根据漏掉、命中、开始和结束事件切换反馈类名与文本，不改变核心计时参数。
- `number-clear.js` 无需改变选择或计时逻辑。

## 测试与验收

自动测试需要覆盖：

- 共享样式仍声明浅色配色，并提供游戏页紧凑布局规则。
- 三个游戏页不再使用深色场地、深色选择框或深色数字按钮。
- 打地鼠页面包含醒目反馈样式，控制器在漏掉时添加强调状态，并在命中或重开时清除状态。
- 现有全部 Node 测试继续通过。

浏览器验收使用 1366×768 视口逐页检查：

- 页面初始状态无需纵向滚动即可看到标题、状态、主要游戏区域与开始/操作按钮。
- 三个游戏区域均为浅色且文字、目标和焦点状态具有足够对比度。
- 打地鼠漏掉反馈明显可见，但下一目标仍按原节奏出现。
- 手机宽度下页面可以自然滚动，控件不重叠、不溢出，触控目标保持可用。
